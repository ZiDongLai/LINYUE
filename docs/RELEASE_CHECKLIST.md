# GitHub提交与正式发行的边界

## 本次源码提交

1. 从冻结源码建立独立Git仓库，核对生产与测试文件摘要不变。
2. 选择远程仓库名称、所有者与可见性；确认后上传初始提交，不覆盖其他项目。
3. 上传后核验远程提交及文件集合，记录可追溯的提交SHA。
4. 当前源码没有指定开源许可证；公开可见与授予开源许可分别决定。

## 若今后另行批准对外Release发行

- 审核Debug限定的蓝牙入口与正式功能范围，不直接移除门控或宣称Debug包为正式发行版。
- 确定应用签名与保留数据升级策略；当前Android release配置沿用debug signing，不能当成已建立正式签名体系。
- 密钥与凭据保存在仓库外；新电脑自动生成的Debug证书不能假定与已安装包一致。
- 审核依赖许可、第三方声明、用户说明及真实设备兼容范围。
- 对正式构建执行必要回归与保留数据升级验收，再决定GitHub Release及二进制附件。

以上不是本轮已批准的实现任务。本轮不改业务、版本、安全规则，不自动安装、不清数据、不发布Release，也不继续优化或开发续传。
